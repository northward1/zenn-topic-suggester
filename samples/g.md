コーディングエージェントは、単に「コードの続きを補完するAI」から、「開発者の指示を受けてファイルを生成・編集し、ターミナルでテストやコマンド実行まで自律的に行うパートナー」へと急速に進化しています。

現在主要なコーディングエージェントは、開発元（モデル）**と**動作スタイル（提供形態）の2つの軸で整理すると全体像が非常に掴みやすくなります。

---

## 1. 開発元（AIモデル）別の特徴

### Anthropic（Claude系）

* **代表的なツール**: **Claude Code**, **Claude（Web / API）**
* **特徴**:
* **圧倒的なコード理解力と長文処理能力**: 複雑な設計の理解、大規模なコードベースをまたぐリファクタリング、バグの原因究明においてトップクラスの精度を誇ります。
* **自律タスクの強さ**: CLIツール「Claude Code」は、自然言語で指示を与えるだけで、プロジェクト全体のファイルを読み込み、修正案を作成し、ターミナルでビルドやテストを通して完成させる高い自律性を備えています。



### OpenAI（ChatGPT / Codex系）

* **代表的なツール**: **OpenAI Codex**, **ChatGPT**, **GitHub Copilot（モデルとして採用）**
* **特徴**:
* **高い汎用性とエージェント操作**: コード生成だけでなく、要件定義、ドキュメント作成、問題解決の壁打ちなど開発プロセス全般を広くカバーします。
* **画面・OSの自律操作能力**: マルチモーダル機能や自律操作に強く、UI画面の認識やブラウザ操作と連携した開発アシストに強みを持ちます。



### Google（Gemini系）

* **代表的なツール**: **Google Antigravity**, **Gemini CLI**, **Gemini Code Assist**
* **特徴**:
* **超長文コンテキスト（100万トークン〜）**: プロジェクト全体のコードや大量のライブラリドキュメントを丸ごと読み込ませて質問・修正させることが得意です。
* **マルチエージェント＆マルチモーダル**: テキストだけでなく画像やデザイン案を直接読み込んでコード化可能。「Antigravity」のような複数のAIエージェントが協調して動く開発プラットフォームを展開しています。

## 2. 動作スタイル（ツールの形態）別の特徴

ツールの使い勝手や作業スタイルに応じて、主に4つの形態に分類されます。

```
【CLIエージェント型】   ターミナル操作＋自律実行（Claude Code, Gemini CLI）
【AIファーストIDE型】  エディタ・チャット・エージェントの一体型（Cursor, Devin Desktop）
【IDE拡張型】           既存VS Code等に組み込み（GitHub Copilot, Cline）
【仕様駆動 / 開発支援型】 要件定義〜開発を構造化（AWS Kiro）

```

| 分類                                | 代表ツール              | メリット                                           | こんな人・用途におすすめ |
| ----------------------------------- | ----------------------- | -------------------------------------------------- | ------------------------ |
| **CLI（ターミナル）エージェント型** | Claude Code, Gemini CLI | ・コマンドラインから直接プロジェクト全体を操作<br> |

<br>・ファイル修正〜テスト実行まで自律的に連鎖処理 | 大規模なリファクタリングや、ターミナル主体の開発を好むエンジニア |
| **AIファーストIDE型** | Cursor, Devin Desktop (旧Windsurf) | ・エディタ全体がAI前提で構築されている<br>

<br>・爆速のTabキー補完とAgentモードを両立<br>

<br>・複数モデル（Claude/OpenAI/Gemini）を切り替え可能 | 日常のメインエディタとしてコーディング速度を極限まで上げたい方 |
| **IDE拡張プラグイン型** | GitHub Copilot, Cline | ・使い慣れたVS CodeやJetBrainsをそのまま使える<br>

<br>・GitHubとの連携（PR作成・レビュー）が強力 | 既存の開発環境を変えずに、チーム運用やGit連携をスムーズに行いたい方 |
| **仕様駆動型（Spec-Driven）** | AWS Kiro | ・コードを書く前に「要件定義書」「設計書」「タスクリスト」をAIが自動作成<br>

<br>・承認を得てから実装に入るためブレが少ない | 設計プロセスを重視するチーム開発や、AWS環境主体のプロジェクト |

## 3. どう選ぶべき？（おすすめの使い分け）

現在の実務では、**1つのツールに絞らず2〜3個を併用するスタイル**が一般的です。

1. **手元でガシガシコードを書くとき** $\rightarrow$ **Cursor** や **GitHub Copilot**
* インラインでのコード補完や、カーソル位置の予測提案でタイピング速度を爆発的に引き上げます。


2. **複雑なバグ調査や複数ファイルの大規模修正** $\rightarrow$ **Claude Code**
* ターミナルから「〜のバグを修正してテストをパスさせて」と投げ、AIに自律調査・修正を任せます。


3. **リポジトリ全体の構造把握・仕様相談** $\rightarrow$ **Gemini CLI** や **ChatGPT**
* 巨大なコードベースやドキュメントを丸ごと読み込ませて、設計の議論や全体像の把握に活用します。
